# Устройство M1

Этап 4 добавляет текущий серверный множитель урона героя, Defense цели и атрибуцию смерти через общий DamageService. Базовые четыре удара сохранены. Формулы и жизненный цикл описаны в [PROGRESSION.md](PROGRESSION.md).

С этапа 3 CombatService применяет урон через общий DamageService: бой разрешён только во время InProgress между действующими враждебными командами. Базы также используют Humanoid, но не получают stun/knockback. Подробности — в [SURVIVAL.md](SURVIVAL.md). Изолированная регрессионная сцена M1 в Studio запускается без правил матча.

## Комбо и серверное время

Одна принятая атака — один шаг. Сервер выбирает шаг и сохраняет startedAt, hitAt, endsAt и nextAttackAt по GetServerTimeNow. На Heartbeat он один раз проверяет hitAt и получает цели в текущем положении персонажа. Пропущенный из-за долгой остановки сервера удар после endsAt не наносит запоздалый урон. Пустой замах также расходует шаг и cooldown.

| Параметр профиля Default | Значение |
| --- | --- |
| DamageByComboStep | 5, 5, 7, 10 HP |
| AttackCooldown / FinisherCooldown | 0,35 / 0,8 с между началами атак |
| ComboResetTime | 1,2 с с начала последней атаки |
| InputBufferWindow | 0,12 с перед доступностью следующей атаки |
| HitDelayByComboStep | 0,10; 0,10; 0,12; 0,18 с |
| AttackDurationByComboStep | 0,28; 0,28; 0,30; 0,55 с |
| HitStunDuration / FinisherStunDuration | 0,25 / 0,65 с |
| MaxStunDuration | 0,8 с для одного события |
| HitboxSize / HitboxOffset | 5×5×5; (0, 0, −2,5) в пространстве корня |
| MaxTargetDistance / MinimumForwardDot | 6 studs / 0,15 |
| MaxTargets | 16 уникальных Humanoid за удар |
| KnockbackVelocity / KnockbackUpVelocity | 35 / 8 studs/s |
| MaxKnockbackSpeed | 45 studs/s для задаваемой скорости |
| AnimationSet / AnimationKeys | Default / Punch1, Punch2, Punch3, HeavyPunch |

Буфер сервера хранит один запрос. Слишком ранние клики, повторный запрос и переполненный буфер отклоняются. Буфер срабатывает на границе cooldown, затем удаляется; просроченный более чем на InputBufferWindow удаляется без атаки. Клиент дополнительно может удержать один клик около границы восстановления, пока ждёт ответ. Очереди не растут при спаме.

После четвёртого удара следующий шаг равен 1. Атрибут ComboStep до следующего старта может оставаться 4: это последний выполненный шаг. Пауза также проверяется при следующем запросе.

## Состояния

CombatState — чистый модуль без Instances и таймеров. FighterStateService связывает его с Character/Humanoid и публикует снимки состояния.

- Idle: разрешён старт, если истёк nextAttackAt.
- Attacking: хранится текущий удар; его ещё не наступившее попадание можно отменить.
- Stunned: активная атака и буфер удаляются; новый M1 запрещён.
- Dead: атак нет; новый Character получает новое состояние.

Оглушения используют одну дату окончания: max(старый срок, текущее время + длительность). Они не складываются в очередь таймеров. Новые реальные попадания могут удерживать цель оглушённой; после последнего срока движение восстановится. Финишер дополнительно сбрасывает комбо цели.

Во время stun сохраняются WalkSpeed, JumpPower, JumpHeight, AutoRotate и политика network ownership. Сервер временно получает физику цели, скорость ходьбы/прыжка становится нулевой. По завершении возвращаются сохранённые значения и владелец. При смерти/удалении персонажа активная работа и соединения очищаются; respawn не наследует старый удар. Глобальные подписки создаются один раз.

В этапе 5 AbilityState дополняет M1 состоянием текущего cast. AbilityService требует окончания recovery M1, очищает буфер и устанавливает AbilityId/срок действия; CombatService проверяет этот атрибут перед стартом и попаданием. Расенган использует однократный контакт в коротком окне; Ветряная ладонь поражает до трёх целей. Обе способности используют общий DamageService и отменяются при stun. Подробности: [HEROES.md](HEROES.md).

## Hitbox и отбрасывание

GetPartBoundsInBox выполняется в момент попадания с актуальным CFrame HumanoidRootPart. Он использует ограничивающие объёмы частей тела. Аксессуары, Tool, собственный персонаж и мёртвые цели исключаются. Humanoid дедуплицируются. Проверяются конечность координат, расстояние и направление. Raycast к корню цели блокирует урон сквозь твёрдые препятствия; тела других кандидатов исключены из этого raycast, поэтому удар может поразить несколько бойцов. [WorldRoot API](https://create.roblox.com/docs/reference/engine/classes/WorldRoot).

TakeDamage учитывает ForceField: без фактического уменьшения Health не возникают stun, knockback и hit-feedback. Смертельный удар переводит цель в Dead, не толкает уже мёртвую сборку.

KnockbackService берёт горизонтальное направление от атакующего к цели. Blockcast небольшого объёма вперёд сокращает скорость возле стены. Сервер задаёт ограниченную целевую скорость через ApplyImpulse с учётом массы и текущей скорости, поэтому собственные импульсы не накапливаются бесконечно. Закреплённые сборки не толкаются. [BasePart API](https://create.roblox.com/docs/reference/engine/classes/BasePart).

Это защита от экстремального собственного импульса, а не универсальная гарантия физики для любых коллизий/скриптов карты. Углы, движущиеся препятствия и нестандартные тела входят в ручной план.

## Сеть и предсказание

BasicAttack принимает ровно два аргумента: целый возрастающий requestId и точный текущий Character отправителя. Клиент не выбирает урон, шаг, профиль, stun, цель, knockback или координаты. Прежний запрос без аргументов больше не используется.

Token bucket: всплеск 6 запросов, восстановление 8/с. Некорректные запросы тоже расходуют лимит. Числа NaN/Inf, лишние аргументы, неверный Character и повторные номера отклоняются. Номер и лимит сохраняются в сессии игрока между respawn; данные удаляются при выходе. Ответы при превышении лимита ограничены интервалом 0,25 с.

CombatEvent передаёт State, Started, Buffered, Rejected и Hit. Снимок содержит Character, профиль, revision, состояние и времена. Клиент применяет только снимки своего текущего Character, не старее уже принятой ревизии. Чужой Started даёт лишь локальный визуальный сигнал, не запускает собственное комбо.

Локальная атака начинается сразу, если доступна. Подтверждение того же requestId/шага корректирует время существующего трека вместо запуска с нуля. Отказ восстанавливает серверное состояние; stun/death прекращают предсказание. Просроченное ожидание очищается через 1,5 с. Урон никогда не предсказывается. Rollback и компенсация исторических позиций не реализованы.

Граница защиты: стандартная физика игрока вне stun остаётся с network ownership Roblox. Серверная проверка текущего CFrame не заменяет отдельную валидацию перемещения/телепортов. [Документация Roblox](https://create.roblox.com/docs/scripting/security/network-ownership).

## Эффекты и диагностика

VFXController локально создаёт короткую вспышку, три искры и подсветку повреждённой модели только после подтверждённого Hit. Обычный удар и финишер отличаются размером, цветом, длительностью и shake. Реакция R15-героя дополнена процедурной позой stun в HeroMotionController; отдельного опубликованного flinch-ролика в поставке нет.

На клиенте не более 24 групп эффектов. Удаляются старейшие при переполнении и все просроченные; твины отменяются. Части закреплены и не участвуют в столкновениях/запросах. Один Heartbeat обслуживает очистку. CameraOffset возвращается к сохранённому значению после shake, смерти или смены персонажа. Будущая настройка может вызвать VFXController.SetCameraShakeEnabled(false); также есть VFXConfig.CameraShakeEnabled.

Для hitbox включите DebugConfig.DebugHitboxes = true **в файле**, дождитесь Rojo и перезапустите тест. Сервер начнёт передавать геометрию отладочной коробки, клиент покажет её на 0,15 с; не более 8 коробок одновременно. LogCombat включает сообщения. Верните оба флага в false после проверки. Это визуализация пространственного запроса, не физическая зона урона.

## Добавление профиля

Скопируйте defaultProfile в CombatConfig, измените баланс и зарегистрируйте новый профиль в таблице profiles; для общего набора достаточно изменить DefaultProfile. Добавьте набор собственных ID в AnimationIds и укажите AnimationSet/AnimationKeys. Число элементов DamageByComboStep, HitDelayByComboStep, AttackDurationByComboStep и AnimationKeys должно совпадать; последний шаг считается финишером.

Требования к значениям: положительные интервалы, hitDelay < attackDuration <= cooldown, InputBufferWindow < AttackCooldown, ComboResetTime больше интервала между ударами. Текущий контроллер рассчитан на четыре шага; VFX.Swing выбирает руку по чётности шага. Для нового типа траектории расширяйте HitboxService и профиль, не принимайте форму от клиента.

Будущий серверный выбор героя назначает fighter.profile и fighter.profileId вместе до начала боя/после respawn, затем Publish. При переключении посреди боя сначала отмените активный удар, буфер и старое состояние. Клиент получает profileId со снимком. Система выбора героев сейчас отсутствует; не назначайте профиль по непроверенному клиентскому аргументу.
